# Arkiv plugin consumer guide

This installable package combines namespaced Arkiv skills, the hosted Mumbai MCP connection at `https://mcp.arkiv.network/mumbai` and a small SessionStart rules hook. Start an Arkiv task with `/arkiv:arkiv`, then load only the task guidance it recommends. It does not install the SDK, provide a wallet, sign or broadcast transactions.

Before executable SDK calls, inspect the project's manifest, lockfile and installed declarations. Ask for missing local evidence. Before a model, ask for the required queries, expected size, public/private fields, creator/owner policy, app stack and Entity Expiration. Before any write, obtain explicit network, operation, signer and spending scope. Never ask for private keys in chat.

The hook reads the current project's `package.json` only and activates when a dependency field declares `@arkiv-network/sdk`. Node.js 20+ must be on PATH. No package mutation, network access or SDK installation occurs in the hook.

Guidance is imported from a fixed canonical skills revision. Do not edit bundled skill files; changes belong upstream. Maintainers build and verify from the distribution repository root with `node scripts/build-plugin.mjs --check`, `node scripts/check-static.mjs`, `node --test tests/*.test.mjs` and strict Claude plugin validation.

Do not add `CLAUDE.md` to this installable root: it is not loaded and creates a strict validation warning. Read actual `server_status` before trusting event rules; never add another connection or switch profiles on your own. Keep test profiles isolated and unclassified production MCP traffic excluded; behavioral tests use `evals/mocks/arkiv` and `--mocks record --no-publish`. Eval responses are synthetic and do not prove current production status.

Require a successful `server_status` reporting profile `mumbai` and its event identity before saying CONNECTED. This package explicitly selects the ETHGlobal Mumbai event profile through November 10; the byte-preserved canonical MCP skill describes General as the usual plugin default. Follow the configured URL and actual status, without adding another connection or switching profiles. Documentation does not establish live availability.

Before every new signature, run a fresh exact unsigned estimate at latest; stop on estimation errors. For N operations require gas >= max(1_000_000 + 400_000 × (N − 1), 2 × estimate) and gas <= latestBlock.gasLimit / 2, within authorized balance/spend. Split unprepared work when it does not fit; stop rather than silently changing a frozen plan. Allow at most one retry per operation, only after an authoritative reverted receipt proves gas exhaustion (gasUsed === gasLimit) and the SDK did not report success. For that retry obtain a fresh latest estimate, use at least double the previous gas cap while satisfying both gas bounds, and refresh nonce and gasPrice under exclusive signer custody. Never resend after SDK success or an uncertain submission, including the same signed bytes; non-gas reverts are terminal. Preserve hashes, intent and receipt-confirmed progress and repair readback/checkpoints without another send.
