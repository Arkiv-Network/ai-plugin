# Consumer and contributor guide

## Purpose and current state

This repository distributes separate Claude Code (`plugins/arkiv`) and Codex CLI (`plugins/arkiv-codex`) packages with shared `arkiv` identity and version. Codex uses `.agents/plugins/marketplace.json`, the native `.codex-plugin/plugin.json` manifest and `streamable-http` transport. Codex 0.162.1 gives a portable root `plugin.json` precedence and skips its hooks, so do not add one. The Codex package carries only its own context hook, never Claude's rules hook. Version 0.3.0 adds the local SDK context hooks to both clients; later releases follow the version and tag rules below. Read README.md for consumer installation. The marketplace is at `.claude-plugin/marketplace.json`; its plugin is nested at `plugins/arkiv` so this repository's existing `CLAUDE.md` pointer is outside the plugin's strict validation surface.

## Configuration and commands

Node.js 20+ runs the rules hook, header helper and maintenance commands. The MCP connection remains usable without Node on the tested Claude Code 2.1.300 host, with no attribution header or automatic rules. Windows checks used Claude Code 2.1.296; this tested version is not a claimed CLI minimum. There are no package dependencies to install. Generated manifests, hosted MCP configuration, hook configuration and the short rules snippet come from `plugin.config.json` and `source/always-on.md`:

```bash
node scripts/build-plugin.mjs
node scripts/build-plugin.mjs --check
node scripts/check-static.mjs
node --test --test-concurrency=1 tests/*.test.mjs
claude plugin validate --strict .
claude plugin validate --strict plugins/arkiv
git diff --check
```

Set `ARKIV_TEST_TMP` to an owned temporary directory if the host requires test artifacts in a specific location. Run test files serially so source-import checks do not compete with hook startup measurements. The timing test measures actual Node startup and requires p95 below 200 ms; measurements depend on machine load. Preserve a first failure and diagnose load before repeating it. The hooks perform no network requests or project mutations. Source for the context hooks lives in `source/context/` and is copied byte for byte into both packages by the build; `scripts/prepare-context-candidates.mjs` derives the no-context control from the release packages for ablations.

To import or verify canonical guidance, use a local clone containing the exact full Git revision in `plugin.config.json`:

```bash
node scripts/sync-skills.mjs /absolute/local/skills-clone --write
node scripts/sync-skills.mjs /absolute/local/skills-clone --check
```

The script reads fixed Git objects rather than the clone's working tree and writes no source checkout. `source/skills.lock.json` schema 2 binds both host destinations, Git blobs, SHA-256 digests and byte counts. Skills remain byte-identical across hosts. It refuses symlinks and unexpected bundle files instead of deleting them. Current active skill content must stay byte-identical to the selected canonical commit. Change guidance upstream, then explicitly update the full revision and import it here.

The historical eval import is pinned separately in `scripts/import-evals.mjs`. Re-import only before freezing evaluation inputs; authored cases remain separate. `source/evals-import.json` preserves original prompt/rubric digests and retirement reasons. See `plugins/arkiv/evals/README.md` for the native ablation command and grader semantics.

## Invariants

- All Arkiv-facing text and examples are in English.
- Skills are authored in Arkiv-Network/skills. Import a fixed reviewed revision for a release, preserve licenses and references, and verify generated bytes.
- 0.4.x bundles exactly `https://mcp.arkiv.network/`, the General profile with Arkiv building guidance and pointers to active event profiles. The human adds an event URL when needed. CONNECTED requires a successful `server_status` reporting profile `general`. Since 0.4.1 the pinned canonical `arkiv-mcp` skill describes this General connection, the separate event profiles and the frozen Devfolio profile; never edit its imported bytes here. It does not fork or embed another backend. Read actual `server_status` before trusting event rules; never add a second connection or switch profiles on your own.
- The private organization MCP repository and the maintained hosted gateway are separate existing sources until their owners reconcile them. Do not claim their release states are equivalent.
- Never publish private service source, local operating notes, credentials, or user data as part of packaging.
- Do not modify service deployments, account settings, user profiles, or the Hub as a side effect of plugin implementation.
- Repository preparation, static validation, and actual consumer installation are distinct evidence.
- Keep repository `CLAUDE.md` as its existing `@AGENTS.md` pointer. Never add a `CLAUDE.md` inside `plugins/arkiv`: Claude Code does not load it and strict validation warns.
- Bump `plugin.config.json` version for any bundled skill, hook, MCP configuration or rule change, then regenerate. Do not repeat the version in the marketplace entry. Tag a verified release with the supported `claude plugin tag` command after checking its current help; never tag an unverified candidate.
- Preserve imported skill license declarations. No repository-wide upstream LICENSE was present at the current source revision; do not invent one or add plugin license metadata until the maintainer confirms the distribution license.
- Claude skills are `arkiv:<name>`; Codex invokes the router with `$arkiv`. Package-root AGENTS.md does not inject consumer rules; explicit project-rule additions preserve existing instructions. CLI evidence does not certify desktop, IDE or web. The deprecated compatibility stub is intentionally absent in both direct and marketplace loading.

## Isolated tests and telemetry

Connection attribution is enabled by default. Generate only the fixed `X-Arkiv-Client: arkiv-plugin/<version>; host=claude-code|codex` value. Claude's generated `scripts/client-headers.mjs` omits it when `ARKIV_TELEMETRY=off`. Only exact `ARKIV_AUDIENCE=internal`, for Arkiv machines, adds the fixed audience header independently; it reads no files, makes no network request and adds no agent context. Never interpolate arbitrary environment values into a telemetry header. Codex uses a static client header and has no package environment-variable opt-out or bundled audience header. Neither path collects skill usage or sends SDK state; the SDK context hook only adds local categorical facts to the agent's context. Preserve the no-network hook invariant. Header attribution never authorizes signing, feedback or another connection.

Before any plugin command, record the SHA-256 of the user's existing Claude settings, known-marketplace and installed-plugin files. Set `CLAUDE_CONFIG_DIR` and `CODEX_HOME` to new owned directories for tests; project scope alone does not isolate shared marketplace/plugin caches. Verify the original hashes afterwards. Never restore or overwrite user settings to hide a difference. Install/uninstall only the resources created by the test.

Native sessions auto-connect plugin MCPs. Use `--strict-mcp-config --mcp-config <safe-local-config>` and first prove the bundled server is suppressed. If that override does not suppress it, use an owned scratch copy with its MCP endpoint replaced by a loopback fixture. Never health-check General in tests. Eval runs use `--mocks record --no-publish` and must never enable real servers. Synthetic feedback and outcome tools may run only against local sinks; this suite exposes read-only mocks only.

The public General endpoint does not currently classify tests with known verification keys. Do not send direct fetch/curl requests or run `claude mcp list` against it. Any authorized remote test must use the existing operator tooling, verify `trafficClass === 'verification'` before other calls, and respect operator pacing. Tokens remain in environment variables, never logs or source. Missing credentials are a coverage limit, not a reason to change credentials or ask for them in chat.

Use an operation deadline for installs, native sessions and eval runs. Inspect actual exit state and fresh artifacts when progress stops. Preserve first-run failures, separate harness/provider problems from product defects, and never weaken an outcome rubric to obtain a pass.

## Required developer inputs

Ask only for decisions that available source evidence cannot answer:

- Existing package/lockfile/installed SDK declarations, or permission to obtain them before executable SDK code.
- The requested screen/query, filters, sort and expected cardinality; stable application IDs and trusted creator scope.
- Which fields can be public, who may create/update, and the retention or Entity Expiration policy.
- Browser-wallet versus server architecture, application authentication, and signer custody. Never request signing keys in chat.
- For any write: explicit operation, network, authorized signer and spending scope. Plugin installation does not authorize a transaction.

Use current official Claude Code plugin, marketplace, hooks and eval documentation. Test actual consumer installation before advertising release availability. The service owner remains responsible for backend changes; this repository packages the existing public connection only.

## Test-only Preview packages

`node scripts/build-plugin.mjs --test-preview https://arkiv-mcp-general-a1b2c3d4e-golem.vercel.app/ --output /absolute/new-directory` creates a separate, unpublished fixture for the orchestrator. Only the exact HTTPS immutable General host shape with nine lowercase alphanumeric characters and a trailing slash is accepted. This command makes no network request. Release configuration always requires the exact production root URL. The output has test-only markers, prerelease manifests and a non-release configuration; normal build/check, `npm run validate`, `npm run release:check`, npm packing/publication and `npm run tag` refuse it. Never tag or publish it, including by bypassing the gate with a raw host command. Use `npm run tag` for the checked release path after the orchestrator verifies all release gates. Validation and tagging are separate from installation evidence.

`ARKIV_TEST_NATIVE_INSTALL=1 npm test` enables bounded native installation checks when `ARKIV_TEST_CLAUDE_BIN` and `ARKIV_TEST_CODEX_BIN` point to the installed CLIs. Each check creates both host profiles under `ARKIV_TEST_TMP`, copies only the packages and local marketplaces, replaces the endpoint with a loopback fixture before installation, verifies the installed bytes, and opens no model session. No production MCP test is part of this suite.
